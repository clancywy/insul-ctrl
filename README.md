线上入口：https://clancywy.github.io/insul-ctrl/ 。手机端由 clancywy/insul-ctrl 的 main 经 GitHub Actions 部署到 GitHub Pages；2026-11-08 发布的 v4.2.0 为前一版本。

2026-11-14 v4.2.1 增加开机、正常关机的 2 秒长按确认。本次发布已获用户授权，只发布手机网页；不连接控制器、不刷固件或操作继电器。离线验证结果为单测22/22、长按交互46/46、一屏23/23，lint及构建通过。

通过手机蓝牙直接连接附近的 InsulCtrl 控制器。安卓使用 Chrome，iPhone 使用支持 Web Bluetooth 的 Bluefy。页面与蓝牙连接需要分别验证；网页发布成功不代表手机或实际接触器已完成验收。

## 当前界面与操作

| 设备状态 | 状态灯 | 手机操作 |
|---|---|---|
| 空闲，已关机 | 绿色 | 开机、启用闹钟、保存时间、同步时间 |
| 设置 | 橙色 | 在控制器旋钮上完成设置；也可取消本地设置（不保存） |
| 闹钟，等待自动开机 | 蓝色 | 取消闹钟 |
| 正在开机 | 红色 | 关机 |
| 已开机 | 红色 | 关机 |
| 等待释放 | 按业务模式取色；正常关机为绿 | 可再次发送关机，禁止启动和修改设置；意外DI单独说明 |
| 时钟异常 | 粉红色 | 同步时间；仍可关机 |
| 设置异常 | 粉红色 | 重新设置并保存；仍可关机 |
| 反馈异常 | 粉红色 | 检查接触器及反馈；输出关闭、DI=0且释放完成后可确认 |
| 状态缺失或过期 | 不显示未经确认的设备灯色 | 仅保留关机，等待状态恢复或重新连接 |

手机“开机”和正常状态的“关机”需持续按住 2 秒：按钮内进度从左到右填满，满时只执行一次，继续按住不会重复发送。短按、提前松手、滑出后滑回均不执行，需要重新按下。键盘 Space/Enter 也采用同样的持续按住规则。断线、状态变化、按钮禁用、切到后台、窗口失焦或打开抽屉会取消尚未完成的长按。

故障、运行中时钟异常和状态待确认时，关机按钮明确显示“立即关机”，仍可点按发送；失败后的关机重试也保持点按。未输入口令仍可长按关机。启用/取消闹钟、保存、同步时间、确认故障和取消本地设置保持点按操作。进度表示手势确认，不表示设备已经执行；发送后继续等待原有回读与失败提示。关机同时取消闹钟。实体旋钮的 2 秒和 10 秒规则不变；时间设置在空闲时修改，RTC、保存和配置故障时保留修复入口。

屏幕和手机统一显示三类故障：`RTC` 为“时钟异常”，`STORE/CONFIG` 为“设置异常”，四种 `FB_*` 为“反馈异常”。详细故障码、DI 回读、保护动作和确认条件保持不变；“⋯”抽屉的设备回读显示诊断（如“E5 吸合超时”），连接记录保留错误原码（如 `E:FB_PICKUP`）。设置异常包含读取失败、记录校验或格式错误，以及保存/回读失败；成功重新保存后清除设置异常，仍需手动启用闹钟。反馈异常未释放时提示检查，满足确认条件才提示确认；实体旋钮长按满 2 秒后松手确认，手机按钮点击确认。

2026-11-08 小修轮的诊断对照如下。屏幕静态故障页脚右侧显示短码，长按进度出现时暂由进度提示替代；手机抽屉由新鲜的 D/F 回读显示原因，重新连接后不依赖历史 E 帧。连接记录保留收到的错误原码，并非记录全部原始帧；记录只在当前页面会话中保存。

| 短码 | 原始故障码 | 原因 |
|---|---|---|
| E1 | RTC | 时钟无效 |
| E2 | STORE | 配置保存失败 |
| E3 | CONFIG | 配置异常 |
| E5 | FB_PICKUP | 吸合超时 |
| E6 | FB_RELEASE | 释放超时 |
| E7 | FB_LOST | 运行中反馈丢失 |
| E8 | FB_INPUT | DI 读取异常 |

反馈满足确认条件仍不代表问题已修好。屏幕提示“检查接触器后长按2秒确认”；手机提示“请检查接触器及反馈接线，再确认。”，按钮为“确认故障”。确认只清除锁存记录、保持空闲；问题未解决，下次开机仍会再报。旋钮是否可确认由硬件状态决定，与手机口令授权状态分开；手机确认仍受原授权规则限制。设置页静态页脚改为“2秒保存”，保存时分后仍需手动启用闹钟。

`OUTPUT` 不作为日常独立故障分类。控制器正式运行致命退出时，先走原关断和清理流程，再尽力绘制一次“正在恢复／请等待设备重启”；画失败仅记录日志，仍等待看门狗复位，不喂狗、不新增继电器操作。构造未完成或显示故障时不能保证出现该画面。清理阶段状态灯关闭，恢复页不重新点灯。手机通常只会收到退出前的 `E:OUTPUT` 浮层；“设备恢复中”整页是保留的兼容分支，不能假定本固件会继续发送故障 D 帧。

2026-11-07 的故障简化与“反馈检查”标题已有下装记录；本次诊断码、页脚和恢复路径仅更新源码，未刷写。手机 v4.2.0 于2026-11-08按单独授权发布，控制器固件不随网页发布更新。历史证据见项目 `output/feedback_check_title_20261107/下装核查记录.txt`；小修轮见 `output/minor_fix_20261108/`。

一屏布局：顶部整块状态色带、当前时间、可编辑的大号闹钟时分，底部固定操作区；旋钮说明、连接记录和断开放入“⋯”抽屉。普通页面不滚动；极短屏叠加口令或红条时，内容区允许有限滚动，底部操作仍留在屏内。

已连接时，短时提示浮层放在操作区上方，避免覆盖状态名称或按钮；未连接时保留入口页的提示位置。

动作按钮保留400ms防连点，取消闹钟（M:0）也受此约束，防止连点“启用闹钟”后又立即取消。长按满2秒的正常关机、异常状态的点按关机及关机重试都将R:0直接送入原停止通道，不受防连点拒绝；未满2秒的正常关机不会生成命令。输出关闭后开机/启用锁定5秒、仅取消未开启输出的闹钟锁定2秒，按钮显示剩余秒数。未保存草稿时不能启用闹钟，可保存或还原；未编辑时跟随设备已保存值。

单次发送失败保留队列以便重试；GATT断开或连续两次失败回连接入口。文案按点击时的状态区分：输出开启或状态不明，提示关机风险和现场长按10秒；取消闹钟，提示“闹钟仍可能到时开机”和现场长按2秒取消；输出已关闭时取消本地设置，按普通命令失败处理，名称为“取消设置命令”。

蓝牙写入3秒没有返回时，关机/取消闹钟显示常驻红条“还没发出”，连接标记改为“发送失败”；其他命令显示琥珀条，蓝牙连接标记保持其连接状态。写入完成后才等待确认，相关回读时间戳必须晚于写入完成；写入卡住期间收到的回读不能在稍后冒充成功。写入完成3秒仍未确认时显示琥珀条，已有常驻红条保留。已连接与已发送都不能替代DI确认。

关机或取消闹钟在写入中、写出后等待回读、或超过3秒仍未确认时断线，均保留停止风险的常驻提示：已有失败红条继续保留，没有失败红条时新增“未确认”提示。关机记录在同一设备新回读确认输出关闭且空闲后清除；取消闹钟记录在同一设备新回读确认离开闹钟状态后结束，包括已取消或已到点开机，避免继续指导运行中的用户长按2秒取消。其他设备的回读不能清除该记录。迟到但有效的命令确认会同时清除对应命令的琥珀条，保留无关提示。

断线保留断开前状态，提供一键重连；仍可扫描其他设备。连接过程可取消；15秒超时从选中设备后的GATT阶段开始，系统设备选择器等待时间不计入。关闭系统选择器不报错；取消或超时后晚到的旧连接会被清理。

“已开机”必须同时获得输出开启、DI=1、反馈阶段已确认三个条件。仅收到开启命令时显示“正在开机”。等待释放不表示接触器已经释放。连接状态与设备状态灯分开显示。

触发时间使用控制器回传的实际目标时刻，按 UTC+8 显示，字号与当前时间一致。闹钟过零不会自动跳到第二天。掉电后保留保存时间，但需要手动重新启用。

## 协议

BLE 服务 `0000aaaa-0000-1000-8000-00805f9b34fb`，命令特征 `0000bbbb-0000-1000-8000-00805f9b34fb`。每次连接或重连发送 `Q`，订阅 `S/D/F/C/N` 详细回读。保留 `R:0/1`、`M:0/1`、`A:HH:MM`、`T:Unix秒` 和 `F:0` 故障确认。S帧只更新兼容字段，不再覆盖D帧中的业务模式。

收到`X:a,n`后支持6位数字口令`P:dddddd`和复位提示。未授权时只保留关机等允许动作；成功后按设备标识存到本机localStorage，重连自动尝试，错误PIN清除，抽屉可手动清除。口令不写连接记录。此功能是误操作防护，不是蓝牙链路加密。

无X帧的v6不要求口令，也不承诺尚未实现的“RTC无效仍可本地10秒开机”；收到X帧后才显示该新版固件提示。支持运行中RTC故障的粉红运行页及复位提示，以便第2次固件交付后配合使用；本轮没有在固件侧实现这些后续能力。

状态、故障、DI 和时钟帧分别检查 3 秒有效期。任何一类过期时禁止开启；单独时钟心跳不能延长旧 DI 状态的有效期。GATT 写入串行执行，停止清除尚未发送的普通命令，断线废弃旧连接队列。页面不使用模拟设备或手机时间代替控制器回读。

历史 v4.2.0 小修轮验收证据见项目`output/minor_fix_20261108/evidence/`；历史交付原样保留。该轮浏览器检查为100项流程、23组一屏，另有16项补充和6项边界检查；这些结果属于当时的点按版本，不能替代当前长按交互验证。

v4.2.1 的检查、截图及改动前备份保存在`output/playwright/mobile_hold_20261114/`。模拟BLE只注入独立离线副本，不进入生产源码或构建；不访问控制器。长按检查使用真实浏览器输入，覆盖阈值前松手、滑出、取消、后台/断线/状态变化、一次触发、异常立即关机和设备回读等待。原协议与展示单测保持不变。
